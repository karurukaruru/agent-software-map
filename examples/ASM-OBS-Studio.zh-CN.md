# ASM：OBS Studio

> OBS Studio 是用于实时音视频采集、合成、录制和直播的免费开源软件。

## 0. 身份

| 字段 | 内容 |
|---|---|
| 名称 | OBS Studio |
| 版本 | 32.2.1 文档候选版；操作前核对实际安装版本 |
| 类别 | 录制、直播、实时音视频合成 |
| 平台 | Windows、macOS、Linux |
| 许可证 | GPL-2.0-or-later |

> **范围：** Profile、Scene Collection、场景、来源、预览、音频混音器、视频与输出设置、Studio Mode、本地录制、诊断和 WebSocket 安全。暂不覆盖插件开发和全部编码器调优。
>
> **置信度：** 基于官方文档，尚未在目标电脑实测。界面名称和可用采集方式、编码器会随平台、语言、硬件和版本变化。OBS 32.2 把“添加来源”下拉菜单改成了新对话框，因此旧版截图可能不同。

## 3. 功能卡片

### [工作区隔离 > Profile] 隔离输出设置

- **作用：** 将测试用的直播、输出、音频和视频设置与已有配置分开。
- **入口：** `Profile` 菜单。
- **操作：** 新建或复制 Profile → 使用唯一测试前缀 → 切换后核对当前名称 → 只在其中配置输出。
- **成功检查：** 新 Profile 已激活，原 Profile 未改变。
- **补丁：** Profile 不保存场景和来源；这些属于 Scene Collection。切换后重新核对服务、分辨率、录制路径和音轨。

### [工作区隔离 > Scene Collection] 隔离场景和来源

- **作用：** 不影响用户已有画面布局。
- **入口：** `Scene Collection` 菜单。
- **操作：** 用唯一测试前缀新建集合 → 切换 → 添加测试场景和来源 → 重新观察混音器。
- **成功检查：** 新集合已激活，原场景未改变。
- **补丁：** Scene Collection 不保存输出设置，因此还需单独使用测试 Profile。

### [画面合成 > 场景和来源] 创建布局

- **作用：** 创建演示、待机等完整画面。
- **入口：** Scenes 与 Sources Dock 的 `+`。
- **操作：** 新建场景 → 选中场景 → 添加颜色、文字、窗口等来源 → 调整层级和可见性 → 完成后锁定。
- **成功检查：** 每个场景在 Preview 中显示预期布局，来源顺序正确且已锁定。
- **补丁：** 来源列表越靠上，画面层级越靠前。“添加已有”会共享同一个来源对象；隐藏不等于删除。

### [画面合成 > Window Capture] 只采集指定窗口

- **作用：** 避免把整个桌面、通知或其他窗口录进去。
- **入口：** Sources → `Window Capture`，不同平台名称可能不同。
- **操作：** 未指定窗口时先询问 → 添加窗口采集 → 选择准确窗口 → 核对 Preview → 必要时裁剪。
- **成功检查：** 只有指定窗口可见，桌面和无关窗口不可见。
- **补丁：** 用户要求窗口采集时不要改用 Display Capture。黑屏时应检查最小化、权限级别、硬件加速和采集方式，不要盲点。

### [画面合成 > 变换与锁定] 无拉伸地适配画布

- **作用：** 保持比例地放置来源。
- **入口：** Preview 变换框或来源右键 → Transform。
- **操作：** 选中来源 → 等比缩放或适配 → 必要时裁剪 → 检查边缘 → 锁定。
- **成功检查：** 无明显拉伸，重要内容可见，且不会被误拖动。

### [音频 > 混音器检查] 识别有效和重复采集

- **作用：** 确认实际有信号的音频路径，防止重复采集或反馈。
- **入口：** Audio Mixer 与 Advanced Audio Properties。
- **操作：** 播放已知声音并观察电平 → 找出活动声道 → 比较全局设备和场景音频来源 → 仅在有理由时静音。
- **成功检查：** 所需音频有信号，无不必要的重复声道或反馈。
- **补丁：** 不能只看来源名字判断；未经允许不要为了让电平跳动而更换系统音频设备。

### [输出 > 视频和录制设置] 配置 720p30 本地录制

- **作用：** 获得可预测、可恢复的测试文件。
- **入口：** Settings → Video；Settings → Output → Recording。
- **操作：** 只在测试 Profile 内设输出为 1280×720、30 FPS → 选择可写路径 → 在可用时选择 MKV 等抗中断容器 → 使用本机实际可用编码器 → 应用后重新打开检查。
- **成功检查：** 分辨率、帧率、格式、路径和编码器保持为所选值。
- **补丁：** 不要假设本机一定有 NVENC、AMF 或 QSV。若最终需要 MP4，可在成功停止后再 Remux。

### [输出 > 开始和停止录制] 生成并验证文件

- **作用：** 录制当前 Program 输出并确认文件可用。
- **入口：** Controls → Start Recording / Stop Recording。
- **操作：** 先确认没有输出正在运行 → 开始录制 → 查看指示器和计时 → 完成动作 → 停止 → 打开录制目录检查最新文件。
- **成功检查：** 录制已停止，新文件存在且大小非零；环境允许时回看片段。
- **补丁：** 绝不能把 Start Streaming 当作替代。不要自行删除测试文件。

### [导播 > Studio Mode] 先预览再转场

- **作用：** 在不改变 Program 的情况下准备下一画面。
- **入口：** Controls → Studio Mode。
- **操作：** 开启后辨认 Preview 与 Program → 初始场景送入 Program → 在 Preview 准备下一场景 → 设置转场 → 执行并检查 Program。
- **成功检查：** 只有执行转场后 Program 才改变，Preview 可独立准备。
- **补丁：** Preview 中可见不等于已经输出，必须检查 Program。

### [安全与诊断 > 输出状态] 操作前检查

- **作用：** 避免误改正在直播或录制的生产环境。
- **入口：** Controls、状态栏、计时器和状态指示。
- **操作：** 检查直播、录制、回放缓冲和虚拟摄像头 → 报告活动状态 → 如果正在输出，暂停并请求用户决定。
- **成功检查：** 所有相关状态明确，风险操作只在隔离且非直播环境中开始。
- **补丁：** 不得在截图、日志或报告中展示串流密钥和密码。

### [安全与诊断 > 日志和 WebSocket] 用证据诊断并保护远程控制

- **作用：** 根据明确错误排查，并安全启用获批的远程控制。
- **入口：** Help → Log Files；Tools → WebSocket Server Settings（具体名称随版本变化）。
- **操作：** 安全复现一次 → 检查对应时间的错误 → 分享前脱敏；只有确有需要才启用 WebSocket → 限制监听范围 → 开启认证 → 用可信客户端测试。
- **成功检查：** 报告引用明确错误且无敏感信息；只有获批客户端能连接。
- **补丁：** 日志可能包含机器和账号信息；不要禁用认证或把密码写进 ASM。
